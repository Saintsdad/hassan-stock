README

How this plan is used

Full text: README.md

Every one of the 406 rows in feature-test-matrix.csv is a unit of work, and every row follows the same five-step contract, from a one-line defect fix to the Windows kernel driver:

1 · Matrix row

Pick a row. Its requirement and acceptance_test fields define what "done" means — not a paraphrase of them.

2 · Failing test first

Write the test named by acceptance_test, tagged with the row's test_id. It must fail before any implementation exists.

3 · Implement

Write the minimum code to make that test pass, per the architecture in this plan.

4 · CI green

All gates for the row's area pass — not just the new test.

5 · Cross-model review

The other model reviews the diff before merge. Opus reviews every Flash PR and holds merge authority; Flash gives a non-blocking mechanical pass on Opus PRs.

Opus 5 does the hard and critical work: architecture, audio-thread code, DSP algorithms, drivers, protocol/state-machine code, security, and adversarial review. Gemini 3.8 Flash does volume work: test generation, golden fixtures, wrapper bindings, docs, UI widgets, CI plumbing, mechanical refactors — and never touches audio-thread code without Opus review. A human decides the open questions in Section 05 and is the final gate on the driver workstream.

01

Scope & architecture

Full text: 01-scope-architecture.md

Build the Max feature set only — not Standard, not Plus. Every row targets Max-level functionality: the full 34-in/64-out routing matrix, all FX, the full NetAudio stack, Macro Buttons, the full Remote API surface, and the Part 3 network use cases. Fixing the reference's Part 2 defects is in scope by design: undo/redo, auto device reconnect, per-app volume, resizable/DPI-aware UI, an optional clock-sync transport, an optional encrypted transport, no licence nag, CLAP plugin hosting as a later milestone. These are load-bearing requirements, not bonus features.

The UI is never in the audio path — it talks to the engine only through the control protocol, the same protocol Stream Deck, Companion and custom scripts use. That is what makes the UI swappable and screenshot/a11y-testable independent of the engine.

Highest risk · Windows kernel driver

Signing: since the April 2026 breaking change, legacy cross-signed drivers are no longer trusted — only WHCP certification or attestation signing with an EV/Azure Trusted Signing certificate remain, each with its own ongoing compliance load. HVCI: drivers must meet HyperVisor-protected Code Integrity requirements. The 24H2 lesson: the reference documents a real incident — leftover outdated virtual-audio drivers caused a Windows 11 24H2 compatibility hold and crashes, fixed only by reinstalling. Not hypothetical. SDK not vendored: ACX/WDK are supplied locally by whoever builds this workstream, never committed to the repository.

Everything else ships and tests without it — backend-null covers 100% of engine-level tests with no dependency on any virtual device. See 02-workstreams.md for the full treatment and the v1-driver-vs-bridge open question in Section 05.

03

Test kit

Full text: 03-test-kit.md

Every matrix row's test_types field is one or more of nine layers; every area maps to at least one harness; CI gates decide what blocks a merge.

LayerProvesRuns where
unitA function/module behaves per spec, in isolation.Every CI run, every platform.
propertyAn invariant holds across random inputs.Every CI run, backend-null.
goldenOutput matches a reference file within a stated tolerance.Every CI run, backend-null.
integrationMultiple modules work together correctly.Every CI run + platform-specific runs.
interopWire/behavioural compatibility with an independent implementation.Dedicated interop job.
fuzzNo panic/crash/memory-safety violation under adversarial input.Continuous, plus bounded per-PR run.
e2e-uiThe UI produces the right screen and a11y tree.Dedicated Playwright + axe-core job.
perfA latency/CPU/memory budget is met and doesn't regress.Nightly full + lightweight per-PR.
manualWhat CI genuinely cannot confirm.Milestone gate.

Harnesses

Offline render harness

Renders a full session with no real-time callback — same input, same seed, same output, every run. Makes golden/property tests bit-reproducible.

Null/loopback backend

A real (if simple) AudioBackend implementation: in-process ring buffer, virtual clock. Runs every engine, dsp, fx, netaudio, control-api, recorder, macro, midi, routing, scripting and security test.

VBAN interop rig

Streams both directions against PipeWire's module-vban (LGPL-2.1+) and quiniouben/vban (GPLv3, fixture-only, never linked) plus vban-cmd for TEXT/SERVICE.

Remote-API shim conformance

Runs the compat shim against the actual existing python/Go/Node wrapper libraries — an ABI mismatch a hand-written double would miss.

GUI a11y + screenshot

Playwright's toMatchAriaSnapshot() and toHaveScreenshot() plus axe-core WCAG scanning. A pixel-perfect screenshot with no accessible name is a failing test.

Driver test VM lane

Hyper-V/VirtualBox-class Windows lanes and a macOS runner for the HAL plug-in. Scheduled and milestone-gated, not a per-PR blocker.

Performance budgets

  • Audio-thread allocation: zero, always — enforced by assert_no_alloc, a CI failure not a warning.
  • Audio-thread locking: zero, always — RTSan-class sanitizer pass on Linux/macOS.
  • Parameter-change latency: ~5–10 ms class, regression-gated once the implementation lands on an exact figure.
  • Criterion regression tolerance: ±10% of baseline per benchmarked DSP block, nightly.
  • Multi-room alignment: a documented tight tolerance, materially better than the plain-protocol baseline.

Adversarial review checklist (Opus → every Flash PR)

  • Does the test implement the row's acceptance_test text, or a weaker paraphrase?
  • Could this test pass against a broken or incomplete implementation?
  • Does the implementation touch audio-thread code, directly or transitively?
  • Are all declared test_types actually present and passing?
  • Does a golden fixture encode the documented tolerance, not an arbitrarily loose one?
  • Is there any hallucinated fact that should cite research notes or be flagged open?
  • Does the PR stay within its one row-group scope?

What Flash must never touch

  • Audio-thread code in any real-time callback path, under any circumstance.
  • The security area's implementation (tests under Opus's design are fine).
  • Windows kernel driver / macOS HAL plug-in implementation.
  • ASIO SDK integration glue.
  • Merge action on its own PRs, or CI gating rules themselves.
  • The control-protocol's parameter grammar or wire-format definition.

Critical path

M0→M1→M2→M3 is the strict sequential spine. M4 can run in parallel with M2/M3 once M1 exits. M5 needs M2+M4. M6 needs only M1+M4 and can run substantially in parallel. M7 is strictly after M4; M8 is last. The Windows kernel driver is the single longest pole, tracked separately from M0–M8 by design.

Top risks (of 10 — see full doc)

  • Windows driver signing/certification timeline — WHCP/HLK lead time is outside this plan's control.
  • VBAN v13 spec inaccessible to research — Opus must read the actual spec; the interop rig is the real correctness check.
  • Denoiser/reverb licensing unconfirmed — in-house fallback budgeted if licences can't be confirmed by M3.
  • Audio-thread real-time-safety regressions are easy to introduce invisibly — hard CI gates on every relevant PR.
  • Scope creep into Part 2 disadvantages beyond what the matrix specifies — a new row is how new scope enters, not an unplanned PR.

Open questions for the human

  • Licensing model for the project itself.
  • Naming — OPENMIX is a placeholder throughout.
  • Ship a Windows kernel driver v1, or bridge through an existing virtual-cable product first?
  • MP3 encoder approach: LAME (LGPL) vs. platform delegation vs. dropping encode from v1.
  • Denoiser algorithm licensing, or ship the simpler in-house fallback.
  • Whether AAC support is wanted at all, given patent-licensing complexity.
  • CLAP plugin hosting scope and timing within or after M0–M8.

07

Research notes

Full text: 07-research-notes.md · conducted 2026-09-06, no live re-fetch this session

Models — Opus 5 vs. Gemini 3.8 Flash

  • Opus 5: 1M/128K context, $5/$25 per Mtok, 79.2% SWE-bench Pro, strong on 20+ step coherence.
  • Flash: 1M/64K context, $0.75/$3.75 introductory (through Dec 2026), batch pricing 50% off, caching up to ~90% input savings.
  • Routing principle: ~80% cheap-model / 20% premium traffic outperforms single-model use on cost/latency/throughput.
platform.claude.com pricing & prompting docs · eesel.ai, modellix.ai, layer3labs.io · codeant.ai, morphllm.com benchmarks thin Flash-tier benchmarking

Drivers — Windows, macOS, Linux

  • April 2026: legacy cross-signed drivers no longer trusted; WHCP or attestation signing + HVCI required.
  • ASIO SDK dual-licensed GPLv3/proprietary since Oct 2025; single device open at a time by design.
  • macOS: AudioServerPlugIn (user-space) preferred over AudioDriverKit (kernel dext, reported sleep hangs).
  • Linux: PipeWire virtual sinks/filter-chain, stable and low-risk.
github.com/microsoft/Windows-driver-samples licence unverified · learn.microsoft.com driver-signing docs · librearts.org (ASIO relicensing) · docs.pipewire.org

DSP — crates, safety tooling, test methodology

  • assert_no_alloc and RTSan for realtime-safety enforcement; FTZ/DAZ for denormal handling.
  • Permissive SRC (rubato, MIT) and biquad formulas; reverb via patent-free Freeverb/Dattorro/FDN designs.
  • Golden tests with tolerance bands, THD+N/SNR, property tests via proptest, seeded deterministic offline rendering.
crates.io/lib.rs (CPAL, Rubato, assert_no_alloc) · github.com (NIH-plug, RTSan, RNNoise licence unconfirmed, DeepFilterNet licence unconfirmed)

Network & UI — VBAN, security, GUI toolkits

  • VBAN v13 (Sep 2025): UDP port 6980, 5 sub-protocols. spec PDF inaccessible to research
  • Interop fixtures: quiniouben/vban (GPLv3), PipeWire module-vban (LGPL-2.1+), out-of-process only.
  • Sync-transport precedents: Roc Toolkit (MPL-2.0), AES67/PTPv2, Noise Protocol Framework (public domain).
  • GUI: egui/iced (permissive) over JUCE/Slint/Qt (AGPL/GPL/commercial-tier licensing).
vb-audio.com · github.com/quiniouben/vban · docs.pipewire.org · roc-streaming.org · noiseprotocol.org · playwright.dev (aria-snapshots)
