# Research notes (condensed)

Condensed from `research/01-models.md` through `research/04-network-compat-ui.md`. Full detail lives in those files; this is the load-bearing subset with sources, and every item the original research itself flagged unverified is marked the same way here — do not treat a condensation as new confirmation.

Research was conducted 2026-09-06 with no live web access from this session; all URLs below are as cited by the original research and were not re-fetched.

## 1. Models

**Claude Opus 5**: 1M input / 128K output context, $5/$25 per Mtok (input/output), no long-context premium. Strong on multi-file features, long-horizon coherence (20+ steps), 79.2% SWE-bench Pro. Weak on: verbosity, scope creep on routine tasks, self-verification without being asked. **Unverified**: whether thinking runs by default and can't be disabled at high effort tiers (cost-relevant).

**Gemini 3.8 Flash** (released Sept 2, 2026): 1M input / 64K output, $0.75/$3.75 per Mtok introductory through Dec 31 2026 (rising to $1.50/$7.50 in Jan 2027), batch pricing 50% off, context caching up to ~90% input savings. Weak on: instruction drift over long conversations, algorithmic edge cases, complex multi-file refactors, higher hallucination rate than GPT-5.5/Claude Sonnet on factual tasks. **Unverified**: occasional timeouts/slowness at high effort; the research base for Flash's coding ability generally is thinner than for the reasoning-tier models.

Benchmarks: SWE-bench Verified is being phased out industry-wide (OpenAI found frontier models can reproduce verbatim gold patches) in favor of SWE-bench Pro; Terminal-Bench and Aider Polyglot have no published Gemini-Flash-tier scores as of the research date.

Routing principle: roughly 80% cheap-model / 20% premium-model traffic outperforms single-model use on cost/latency/throughput; aggressive 80/20 cheap/frontier splits can approach ~72% cost reduction.

Sources: platform.claude.com pricing and prompting docs, code.claude.com sub-agents docs, platform.claude.com multiagent-orchestration docs; eesel.ai, modellix.ai, layer3labs.io, benchlm.ai for Gemini figures; codeant.ai, morphllm.com, leaderboard.steel.dev for benchmarks; morphllm.com and blog.saif71.com for AGENTS.md/CLAUDE.md/GEMINI.md conventions; velsof.com and digitalapplied.com for routing patterns; keploy.io for contract testing.

## 2. Drivers

**Windows kernel drivers**: Microsoft's SysVAD sample (`microsoft/Windows-driver-samples`) uses WaveRT/KMDF; **licence unclear from the public repo, unverified — check file headers before copying anything**. ACX (Audio Class eXtension) is Microsoft's recommended modern replacement for PortCls. VB-Cable (commercial, proprietary licence) works XP-SP2 through Win11/ARM64 via Windows driver attestation. The Windows 11 24H2 Voicemeeter compatibility-hold incident (leftover outdated drivers flagged incompatible, fixed by reinstalling/updating) is documented and resolved by late 2024 — cited as precedent, not a current blocker.

**April 2026 signing deadline**: legacy cross-signed drivers no longer trusted; WHCP certification or EV/Azure Trusted Signing attestation required; HVCI compliance required. **Unverified**: exact VB-Cable signing method, Driver Verifier specific audio-driver config, VM CI runner audio-passthrough support (Hyper-V vs VMware).

**Windows user-mode alternatives**: WASAPI loopback + APO cannot create a true virtual multi-client device (apps still see only real hardware) — not viable as a Voicemeeter-class mixer replacement, only for system-wide effects/AEC.

**ASIO**: Steinberg SDK dual-licensed GPLv3/proprietary since October 2025 (previously proprietary-only, incompatible with GPL). Multi-client limitation is inherent to the SDK (one device open at a time); FlexASIO (PortAudio-based wrapper) and WineASIO (ASIO-to-JACK bridge, LGPL-2.1) are existing patterns. `asio-sys` (Apache-2.0) is the Rust binding layer.

**macOS**: AudioServerPlugIn (HAL plug-in, user-space, code-signed + notarized) is Apple's current recommendation over AudioDriverKit (kernel-mode dext, reported sleep-hang issues, still described as actively developed). BlackHole is a public GPL-3.0 example of the HAL-plug-in pattern.

**Linux**: PipeWire virtual sinks/sources and the filter-chain module (LADSPA/LV2/SOFA/FFmpeg filters) are stable and low-risk; JACK remains a viable low-latency alternative with a PipeWire-JACK compatibility layer.

**Host I/O libraries**: PortAudio (MIT, optional ASIO), RtAudio (MIT), miniaudio (public domain, **no ASIO backend**, issue #133 unresolved as of research date), cpal (Apache-2.0/MIT, no ASIO), JUCE (AGPLv3/commercial, full ASIO/CoreAudio/ALSA/JACK support).

Sources: github.com/microsoft/Windows-driver-samples, learn.microsoft.com ACX docs, shop.vb-audio.com and vb-audio.com/Cable manual, minitool.com (24H2 incident), learn.microsoft.com driver-signing-offerings, techcommunity.microsoft.com (cross-signed driver trust removal), neowin.net (Windows-on-ARM audio driver plans), learn.microsoft.com loopback-recording and APO docs, librearts.org (ASIO relicensing), github.com/dechamps/FlexASIO, github.com/wineasio/wineasio, crates.io/crates/asio-sys, github.com/inguyendo/BlackHole-macos, existential.audio/blackhole, developer.apple.com AudioDriverKit docs and forums, docs.pipewire.org filter-chain and virtual-sink pages, jackaudio.org.

## 3. DSP

**Rust audio crates**: CPAL (I/O), FunDSP (processing/synthesis), Rubato (MIT, async resampling), NIH-plug (VST3+CLAP plugin framework, realtime-safe background task runner), Clack (experimental safe CLAP bindings), `clap-sys`.

**Realtime-safety tooling**: `assert_no_alloc` (custom allocator, aborts/warns on forbidden allocation in realtime contexts), RealtimeSanitizer/RTSan (LLVM/Clang 20+, `#[nonblocking]`-annotated functions, Linux/macOS/iOS). Denormal handling via FTZ/DAZ flags, as PipeWire itself does.

**Permissive DSP building blocks with licences**: rubato (MIT) and r8brain-free-src (MIT) for SRC; libsamplerate (LGPL) as an older reference; RBJ cookbook biquads and Vicanek matched-Z biquads as published formulas (MIT when published standalone, otherwise implement from the published algorithm); Freeverb (LGPL-with-exception in GRAME's Faust libs, BSD in some older Faust examples — **verify exact source before copying code**); Dattorro plate reverb and FDN (patent-free published algorithms); Signalsmith Stretch (MIT) for pitch/time-stretch; Rubber Band (GPL/commercial) as the higher-quality alternative if the licence is acceptable; RNNoise and DeepFilterNet as the reference denoiser algorithm class — **licence not confirmed for either in research, do not vendor without confirming**; Resonance Audio (Apache-2.0) and 3D Tune-In Toolkit (Apache-2.0) for binaural/HRTF if spatial audio is ever added; symphonia-bundle-mp3 (MPL-2.0) for MP3 decode, dr_mp3 (MIT) as a lighter alternative, minimp3 (MIT but **deprecated/unsound, avoid for new code**); LAME (LGPL) for MP3 encode.

**AAC/M4A**: patent pool via Via LA, historically a real one-time licensing fee; most legacy MPEG-2/MPEG-4 AAC-LC patents have expired (2017-2023) but not confirmed all have as of the research date — treat as an open licensing question, not a solved one.

**DSP test methodology**: golden/reference tests with documented tolerance bands, null tests (silence/DC/zero input), frequency-domain tests (sine sweep, THD+N, SNR), time-domain tests (step response, latency, impulse response for reverb RT60), property-based testing via `proptest` (NaN/Inf absence, denormal handling, peak-detection bounds, energy conservation, monotonic reverb decay), a deterministic offline render harness with seeded randomness, Criterion for regression-gated benchmarks, `cargo-fuzz` for decoder fuzzing.

**Undo/redo and parameter-graph patterns**: dynamic vs. snapshot automation; Auto Off/Read/Touch/Latch modes as the DAW-standard automation-mode vocabulary; differential (changed-fields-only) state history for undo/redo; parameter graph as a DAG (channels/buses/plugins as nodes, routing as edges); lock-free queue with sample-accurate cross-fade on parameter change (~10 ms) to avoid clicks; typical 5-10 ms scheduling latency between UI change and audible effect.

**Unverified/not found**: no canonical open-source Rust audio test suite was identified as a reference; DeepFilterNet's exact licence; a permissive reference for chorus/phaser implementation (none found, expect in-house LFO+delay/allpass implementation).

Sources: crates.io/lib.rs pages for CPAL, FunDSP, Rubato, assert_no_alloc; github.com for NIH-plug, RealtimeSanitizer, r8brain-free-src, libsamplerate, Signalsmith Stretch, Rubber Band, RNNoise, DeepFilterNet, Symphonia, minimp3; valvesoftware.github.io (Steam Audio), resonance-audio.github.io, 3d-tune-in.eu; tech.ebu.ch (BWF/EBU TECH 3285), itu.int (ITU-R BS.775); via-la.com (AAC licensing); faustlibraries.grame.fr, ccrma.stanford.edu, dsprelated.com (reverb designs); juce.com legal page; rust.audio.

## 4. Network, compatibility, UI

**VBAN protocol**: spec is VB-Audio VBAN Protocol v13 (Sep 2025), UDP port 6980 default, 5 sub-protocols (AUDIO/PCM, SERIAL/MIDI, TEXT, FRAME, PING). **The spec PDF itself was inaccessible to research from the research proxy — this is the single most important unverified item in the whole plan for the netaudio area; Opus must obtain and read the actual current spec before implementing the wire format, not rely on this secondhand description.** Voicemeeter SDK's stated terms (per its GitHub README) allow use "in any kind of project interacting with Voicemeeter through voicemeeterremote DLL or VBAN protocol," with full legal terms in a PDF not independently re-verified here.

**Open-source VBAN implementations** (for interop testing, not vendoring): `quiniouben/vban` (GPLv3, C), PipeWire `module-vban-send`/`recv` (LGPL-2.1+, PipeWire core, available >=0.3.76/1.0.5), `vban-cmd` Python (TEXT/SERVICE subprotocols only), Rust `vban-rs`/`rusty-vban` (**licences not confirmed in research**), `thib3113/vban` Node.js (**unverified**), `norihiro/obs-vban` (OBS plugin), ESP32 VBAN receiver project.

**Remote API compatibility**: no public reference confirms the exact ABI-compatibility legal position of the incumbent's Remote API DLL; treat as proprietary with binary-compatibility expectations only, not a confirmed licence to replicate. Registry-based DLL discovery pattern documented by a third-party dynamic-wrapper project. Alternative control protocols surveyed: OSC (an existing OSC-to-Voicemeeter bridge exists), WebSocket (no direct precedent found), gRPC (used in adjacent audio-adjacent tools, not directly), MIDI 2.0/Mackie Control/HUI (implied support, **not independently verified against the reference**), Ember+ (broadcast-networking protocol, high complexity, not adopted here).

**Open mixers for study**: Ardour (GPL/LGPL), Mixxx, PipeWire (LGPL-2.1+), Carla, SonoBus, Jamulus (custom OPUS stream, not formally secured), Snapcast (multi-room, proprietary sync algorithm not PTP, no encryption).

**Clock-synchronised multi-room**: Snapcast's client-server sync is a proprietary algorithm, not PTP. AES67/RAVENNA uses IEEE1588-2008 PTPv2 with the Best Master Clock Algorithm for sub-nanosecond-class sync — the professional-broadcast reference point, heavier than what a consumer multi-room feature needs but informs the sync-transport's timestamp design. Roc Toolkit (MPL-2.0 main, LGPL-2.1-or-later for PulseAudio modules, CeCILL-C if built with OpenFEC) is a directly relevant open-source precedent for FEC-based packet resilience. Windows 11/Server 2022+ have a native PTP stack (IEEE 1588-2019 draft); enterprise-grade PTP still typically needs a grandmaster clock, which is out of scope for a consumer/prosumer feature.

**Secure transport precedents**: WebRTC's DTLS-SRTP (RFC 5764) is the standard confidentiality/integrity/replay-protection combination for real-time media; QUIC datagrams (RFC 9000/9221) are a lighter-weight unreliable-transport alternative; `boringtun` (BSD-3-Clause, Rust userspace WireGuard) is a relevant precedent for in-app tunneling, though it has no audio-specific features of its own; the Noise Protocol Framework (public domain) is a fitting basis for a custom authenticated-encryption sync-transport mode, following precedents like WhatsApp/Slack rather than adopting DTLS wholesale.

**Ingest/publish**: GStreamer (LGPL-2.1+ for core/base/good; GPL only if `gst-plugins-ugly`-class plugins are pulled in, avoidable here) and FFmpeg (LGPL-2.1+ by default; GPL only via `--enable-gpl`/`--enable-nonfree`) are the two realistic RTSP/RTP/HLS ingest toolkits; `libdatachannel` (MPL-2.0) for WebRTC-class data/media transport if ever needed; `go2rtc`/`MediaMTX` as ready-made RTSP/ONVIF-backchannel sidecars (**their own licences were not independently confirmed in research — check before adoption**); Opus (RFC 6716, royalty-free) as the default real-time codec choice for any new codec-level work.

**Cross-platform GUI**: egui (MIT/Apache-2.0, immediate-mode, DPI-aware via logical points) and iced (permissive, wgpu-based, Elm-inspired) are the two permissively licensed Rust-native options; JUCE (AGPLv3/commercial, $40-$130/month tiers as of the 2026-06-17 JUCE 9 EULA), Slint (GPL-3.0/commercial) and Qt (LGPLv3/commercial, EUR530-4800/year) all carry a licensing decision that egui/iced avoid; Tauri (MIT/Apache-2.0, webview-based) and Flutter (BSD) are cross-language alternatives not chosen here because the rest of the stack is Rust-native.

**GUI test tooling**: Playwright's `toMatchAriaSnapshot()` (accessibility-tree YAML comparison) and `toHaveScreenshot()` (pixel-diff with configurable threshold), plus axe-core for WCAG rule scanning — the combination this plan's `03-test-kit.md` GUI harness is built on.

**Unverified items flagged by this research file directly**: Voicemeeter SDK's exact EULA text (PDF blocked); PipeWire VBAN module's exact compile flags/runtime state (assumed stable at >=0.3.76 but not independently re-checked); Carla's spatial-audio feature set for remote streams; whether Scream (Windows network audio) is still an active project in 2026; Windows PTP stack's production-readiness outside enterprise deployments.

## Reconciliation with the decision spine

Every architecture decision in `decisions.md` is corroborated by at least one research finding used above: the OS-backend-trait pattern matches the host-I/O-library landscape (no single library covers WASAPI+ASIO+CoreAudio+PipeWire cleanly, hence a custom trait over vendored libraries); the null-backend approach is a direct application of the offline-render-harness and determinism findings in the DSP research; the VBAN-plus-sync-transport split matches the precedent set by Roc Toolkit and Snapcast (interop-compatible plain mode plus a separately-optioned higher-quality mode); the compat-shim approach matches the registry-based DLL-discovery pattern found for the incumbent's Remote API; the ASIO-SDK-never-vendored rule matches the October 2025 relicensing event directly. No research finding contradicts a decision-spine item; where research was thin (VBAN spec text, Remote API ABI legal terms, several DSP-block licences), that thinness is called out above and in the relevant workstream/risk sections rather than papered over.
